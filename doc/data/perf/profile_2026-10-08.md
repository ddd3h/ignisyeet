# Run-time profile of the ignisyeet stages (2026-10-08)

Release v0.4.0 (commit b6a9bf5), `examples/sample.toml` (Barrowman unless stated; panel variant =
`--set aero.method=panel`), 4 threads (`--set resources.threads=4`), i7-12700 (20 threads, 30 GB)
**shared with SU2 jobs (load average 12-15 during all measurements)**, so wall times scatter by about
10-30 % between repeats; the ranges below are from two to three repeats. Reproduce with
`doc/scripts/perf_profile.sh SCRATCH_DIR 4`.

Method. `perf` is blocked on this machine (`kernel.perf_event_paranoid = 4`), and valgrind and gdb are not
installed, so profiles come from pprof-rs (SIGPROF sampling at 997 Hz, all threads) in a throwaway copy
of the CLI built with debug symbols. The library crates are used unchanged. Stage timestamps of the panel
method come from its progress events. A separate harness splits one subsonic panel solve into
assembly, LU and solves. Python uses wall-clock times per subcommand plus cProfile. Percentages are shares
of CPU samples. Sub-second runs have only 100-900 samples, so their shares are coarse. The CFD
pipeline was not run: its numbers come from the committed data in `doc/data/cfd/`.

The sample flight is unchanged: apogee 4440.5 m, landing E -655.6 m, N -7707.7 m with rk4. rk45 and
dop853 give the same values to 0.01 m.

### Panel method (32-34 s at 4 threads)

These are phase timestamps from the progress events. Shares are of the wall time.

| Phase | 4 threads | 2 threads | 1 thread | Share (4 thr) |
|---|---|---|---|---|
| mesh (5888 panels + 160 wake) | 0.005 s | 0.01 s | 0.005 s | 0 % |
| 6 subsonic solves (2.2-2.3 s each) | 13.4-13.7 s | 25.4-26.2 s | 44.3-49.8 s | 42 % |
| transonic band edges (4 columns, **serial**) | 1.6 s | 1.9-2.0 s | 2.3-2.4 s | 5 % |
| Mach x alpha column fill (151 columns, parallel) | 16.6-17.0 s | 32.3-32.5 s | 63-64 s | 52 % |
| lag terms + save | 0.1 s | 0.1 s | 0.1 s | 0.3 % |

One subsonic solve, measured with the harness:

| Part | 4 threads | 1 thread |
|---|---|---|
| influence-matrix assembly (n = 5888) | 0.25-0.30 s (12 %) | 0.90-1.06 s |
| dense LU (faer, partial pivoting) | 1.70-1.91 s (75 %), 71-80 GFLOP/s | 5.9-6.1 s, 22-23 GFLOP/s |
| triangular solves (3 RHS) | 0.03-0.05 s | 0.09-0.13 s |
| surface gradient and rest | about 0.2 s | about 0.3 s |

Sampled profile, share of CPU samples:

| Share | Path |
|---|---|
| 58 % | `Ctx::sup_column` → `SupersonicPanels::forces` → `panel_cp` (55 %) |
| 33 % | of which `expansion_cp`: a 70-step bisection, each step calls `prandtl_meyer` (2 `atan`) |
| 23 % | of which `wedge_cp` → `wedge_beta`: a 60-step bisection, each step calls `deflection` (`tan`, `sin`, `cos`, `atan`) |
| 32 % | unattributed stacks (unwinding failed). Their share matches the LU's CPU share (6 x 1.75 s x 4 threads of 121 CPU-s), so they are most likely faer's assembly GEMM kernels |
| 5 % | `influence::influence` (assembly) |
| 1.5 % | visible `lu_in_place` frames |

Primitive costs (single call, M = 2): `expansion_cp` 2.8 µs, `wedge_cp` 3.5 µs, `cone_cp` 13 ns (tabulated),
`prandtl_meyer` 26 ns. `SupersonicPanels::forces` takes 7-10 ms per (Mach, alpha) on one thread, and the
table needs 91 supersonic columns (Mach 1.2 to 3.0 in steps of 0.02) x 91 alphas of it. The fin panels also recompute
`cp0 = panel_cp(m, delta0)`, which depends only on the Mach number, at every alpha.

## 4. Dispersion (the flight RHS)

Wall times at 1 / 2 / 4 threads. The two values in each cell are two runs.

| Run | 1 thread | 2 threads | 4 threads | Speed-up 1→4 |
|---|---|---|---|---|
| wind grid, 112 flights, rk4 | 17.2 / 23.4 s | 8.65 / 9.07 s | 4.56 / 4.85 s | 3.8x (the 23.4 s single-thread run was disturbed) |
| Monte Carlo 1000 x 2, rk45 | 21.2 / 24.3 s | 10.8 / 11.7 s | 5.53 / 5.61 s | 3.8-4.3x |

CPU per flight: rk4 (dt 0.002) about 155-210 ms, rk45 about 11-12 ms, dop853 about 35-40 ms. Up to 4
threads the scaling is close to linear. The memory footprint is 15 MB.

Sampled profile, share of CPU samples (Monte Carlo rk45 / wind grid rk4):

| Share | Path | Note |
|---|---|---|
| 76 / 82 % | `Simulation::deriv` (inclusive) | |
| 19 / 22 % | `AtmosphereModel::at` → `us76` | 2 `powf` per call: pressure `(Tb/T)^k`, and viscosity `T^1.5`, **which the flight never uses** |
| 18 / 20 % | `Wind::at` (power law `powf`) | up to 3 calls per RHS: airspeed plus a ±1 cm central difference for dW/dh (lag term) |
| 27 / 30 % | `powf` self (the two rows above) | us76 14-17 %, wind 11-13 % |
| 8-9 % | `mass_at` | `Motor::propellant_left` recomputes `total_impulse()` per call, also after burnout |
| 6-7 % | `AeroTable::lookup` | `locate` scans the axes linearly (151 Mach, 91 alpha nodes). `record` makes 3 atomic RMWs on shared counters per lookup (1.3-3 %) |
| 2.5-3.3 % | `static_margins` per step | folds the alpha axis for its secant step at every call |
| 8 % / 4 % | integrator algebra (`dopri5_step`, `State::add`, `to_arr`) | |
| 7 % (grid) | `nominal_warnings` | nominal ballistic and parachute flights run **serially** before the parallel batch |

## 5. Keep-out procedure (estimate, not run)

Steps 0-4 of the dispersion chapter (both aero methods, rk45) consist of the following:

| Item | Flights | Cost at 4 threads |
|---|---|---|
| aero tables (barrowman + panel) | - | 32-34 s |
| wind grids: 36 directions x 6 speeds, 360 x 6, 360 x 9 (fine), x 2 descents, both methods | about 16k | about 45 s |
| 30 Monte Carlo runs x 10^4 samples x 2 descents | 6 x 10^5 | 16 min (doc: 32.2 s per run) to 28 min (11 ms CPU per flight here) |
| **total** | | **about 17-29 min, about 96 % Monte Carlo** |

Steps 5-6 multiply these runs. The per-flight RHS cost (section 4) is the only lever that matters
here. The panel table is built once.

| Euler matrix 4 Mach x 4 alpha, 1.42M cells, 4 ranks, 1 case at a time (`run_summary.json`, `sample_euler_cases.csv`) | 9149 s | 9118 s (99.7 %) | 25 s (0.3 %) | about 6 s (0.1 %) |

Per-case comparison:

| | Euler (2 mm, 1.42M cells) | RANS (5 mm, 1.68M cells) |
|---|---|---|
| iterations | 152-352 (median 152) | 402-1352 (median 402) |
| wall per case | 372-904 s (median 523 s) | 854-3678 s (median 1344 s) |
| s per iteration, wall / iterations | 1.8-3.7 (median 3.0) | 2.1-5.2 (median 2.9) |
| cold vs warm start | 372 s (only cold case, 202 iterations) / 583 s (mean of 15) | 2435 s (mean of 4) / 1319 s (mean of 16) |

RANS cases cost about 2.6x Euler cases because they run about 2.6x more iterations (medians 402 and 152). The cost per iteration is
about the same. The gmsh time grows with the cell count, single threaded: 13 s at 0.87M cells and 59 s at
5.8M cells. It never exceeds a few % of a run with more than 2 cases per mesh. The wall times were
recorded on a machine shared with other SU2 jobs, and SU2 start-up (mesh read, partitioning) cannot be
separated from the iterations in the committed data.

## 8. Optimisation opportunities

They are ordered by the expected wall-time gain on the workloads that matter (panel table build, and
dispersion/keep-out). All gains are estimates from the shares above and have not been implemented.

| # | Change | Expected gain | Risk / effect on results |
|---|---|---|---|
| 1 | Panel supersonic Cp: Newton (or a per-Mach tabulated inverse) instead of the 60/70-step bisections in `wedge_beta` / `expansion_cp`. Hoist the alpha-independent `cp0 = panel_cp(m, delta0)` (fins) and the body `cone_or_detached(m, delta0)` out of the alpha loop | column fill 17 s → about 1-2 s. **Panel `aero` 32 s → about 16 s** (1 thread: 116 → about 55 s) | low: same equations, root to round-off. Panel table changes in the last digits. Check with the panel tests |
| 2 | Panel subsonic solve: use the pitch-plane symmetry (all 3 RHS are even in y) to halve the system (LU cost /8, assembly /2). Later, even/odd decomposition about z = 0 as well | subsonic 13.7 s → about 2-3 s. **With #1, panel `aero` about 5 s** | medium: the mesh must be exactly mirror symmetric (fall back to the full system for cant, asymmetric fins, lateral CG). The wake/Kutta columns need care |
| 2b | Alternatively, f32 LU + iterative refinement | LU about 1.5-2x | low-medium (refinement must reach f64 accuracy) |
| 3 | Run the 4 transonic band-edge columns in parallel (`rayon::join`) | 1.2 s at 4 threads (4 %). Small after #1 | none |
| 4 | Atmosphere for the flight without the viscosity (`T.powf(1.5)` per RHS call, unused by `sim`) | **8-10 % of every dispersion/MC run** | none: results bit-identical |
| 5 | Analytic dW/dh for the power/log models (slope of the segment for `profile`) instead of 2 extra `Wind::at` calls per RHS | 10-12 % of dispersion time | low: changes results at the 1e-8 relative level (finite-difference truncation). Re-check the golden sample |
| 6 | Aero lookup: O(1) cell index on the uniform Mach/alpha grids (keep the search for irregular axes). Per-thread or batched out-of-range counters instead of 3 shared atomic RMWs per lookup | 3-5 % at 4 threads, probably more at 20 threads (shared cache line) | low: identical values if node selection is reproduced exactly |
| 7 | Cache `total_impulse()` and the burnt-out mass state in `mass_at`. Precompute the secant step of `static_margins` | 3-5 % | none: bit-identical |
| 8 | Fly the two nominal flights of `dispersion` in parallel with each other or with the batch | 3-7 % at 4 threads, up to about 20-25 % for a 20-thread rk4 grid | none |
| 9 | Fast fixed-precision float formatting for `trajectory.csv` (and the aero CSV) | `sim` rk45 process about 2x faster (0.2 → 0.1 s). Irrelevant for dispersion | low if the bytes stay identical (test against the current output) |
| 10 | Recommend or default rk45 for dispersion. rk4 with dt = 0.002 costs 13x rk45 per flight for the same landing point to 0.01 m. dop853 costs 3x rk45 at these tolerances | 13x for rk4 users | behaviour change (the golden sample is defined with rk4). The docs already recommend rk45 for keep-out runs |
| 11 | Plotting: one process per figure in parallel | about 2x for `all` (about 2-3 s) | low, minor value |
| 12 | CFD: the Rust side is negligible (< 0.3 %). The levers are SU2 iterations: warm starts (RANS cold starts cost 1.8x warm), the acceptance rule and iteration caps, and `parallel_cases` vs `ranks_per_case` | depends on settings | numerics; out of scope here |

Items 4-8 add up to roughly 25-35 % of the per-flight cost, which saves about 5-9 min of the 17-29 min
keep-out estimate at 4 threads. Items 1 and 2 bring the panel table from about 33 s to about 5 s at 4
threads.
